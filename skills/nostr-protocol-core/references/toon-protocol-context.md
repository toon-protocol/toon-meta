# TOON Protocol Context

> **Canonical single source of truth for the TOON protocol.** This file is injected into every skill generated by the NIP-to-TOON pipeline (Story 9.2, decision D9-010). When the protocol changes, update this file and re-run affected skills through the pipeline.
>
> Protocol law itself lives in the connector repo — [`CONTEXT.md`](https://github.com/toon-protocol/connector/blob/main/CONTEXT.md) and [`docs/adr/`](https://github.com/toon-protocol/connector/blob/main/docs/adr/README.md). Anything here that contradicts those is a bug here.

## Protocol Summary

TOON is **payment as a reverse proxy**. A **connector** terminates payments the way nginx terminates SSL: value arrives wrapped in a protocol the service never speaks, and at the last hop the connector unwraps it, verifies it, and hands the service ordinary HTTP that was already paid for. There are exactly two roles, **connector** and **app**.

Pay-to-write Nostr is one application of this, not its definition — and it is the one the fleet runs: the relay app sits behind a connector, so a *write* is a paid packet and *reads* stay free over ordinary Nostr WebSocket, never touching a connector at all.

Every packet carries its own **covering claim**, so nothing is owed between packets and there is no invoice/settle round-trip.

## Write Model

**Transport:** `@toon-protocol/client` (NOT the SDK). Agents make paid writes with `ToonClient.send()`.

**Flow:**

1. Construct and sign the Nostr event exactly as you would on any relay (`nostr-tools`, `finalizeEvent`).
2. `await client.send({ body: signedEvent })`.

That is the whole flow. `send()` seals the payload to the terminating connector, asks that connector what the route costs, mints a covering claim for exactly that amount, chooses a carriage and carries it. A caller never prices a packet by hand, never signs a claim by hand, and never builds an ILP packet.

```typescript
import { ToonClient } from '@toon-protocol/client';

const client = await ToonClient.create({
  connector: 'https://proxy.relay.devnet.toonprotocol.dev',
  mnemonic: process.env.TOON_MNEMONIC,
});

await client.channel.open({ deposit: 100_000n });

const answer = await client.send({ body: signedEvent });
if (!answer.fulfilled) {
  console.error('refused:', answer.code, answer.message);
}
```

**A REJECT is returned, not thrown.** It arrives as `{ fulfilled: false }` with a code. A FULFILL is `{ fulfilled: true, status, headers, body, claim }`, where `status` is the **app's** HTTP status — a 404 from the relay is a real answer and costs what a 200 costs.

**No condition/fulfilment computation on the client side.** Agents never compute SHA-256 double-hashes and never manage ILP conditions (decision D9-005).

**Never use raw WebSocket writes.** A write to the relay app must go through the connector in front of it, because that is where payment is terminated.

**Retired — these do not exist and calling them calls nothing:** `publishEvent()`, a caller-facing `signBalanceProof()`, `basePricePerByte`, `feePerByte`, per-kind price overrides, the `bid` safety cap (D7-006) and the DVM amount override (D7-007) as previously described.

## Read Model

**Subscriptions:** standard NIP-01 filters over WebSocket: `["REQ", <sub_id>, <filters>]`, against the relay app directly (`wss://relay-ws.devnet.toonprotocol.dev`).

**Reads speak plain NIP-01.** The relay returns **standard JSON** `EVENT` messages -- `["EVENT", <sub_id>, {id, pubkey, created_at, kind, tags, content, sig}]` -- and any ordinary Nostr client can read it with no decoder and no TOON awareness at all. The relay contains no payment code; a read never touches a connector.

**Free reads:** no payment, no claim, no connector.

## Where TOON Encoding Actually Lives

TOON is the encoding of the **write payload**: an agreement between a **client and an app** about the bytes the connector carries **sealed** inside the ILP packet. It is not connector law -- the connector never opens those bytes -- and it is **not what a relay serves on a read**.

The rule, in one line: **TOON on the way in, plain NIP-01 JSON on the way out.**

Do not reach for `@toon-format/toon` to parse a relay subscription. Anything telling you a relay returns TOON-format strings, or that you must decode an `EVENT` message, is describing something the deployed relay does not do.

## Discovery

**A connector answers; it never announces** (connector ADR 0022, ADR 0046).

**`GET /ilp`** on a node's URL returns its **self-description**: its ILP addresses, its settlement facts (chain, token, decimals) and **every route's price**. Free and unauthenticated (ADR 0050). This is the only place a node's payment facts come from.

**An unpaid request to a priced route gets a greeting** — that route's terms, never the work. The word is *greeting*.

**Finding a relay to read from is still the Nostr problem it always was** — NIP-65 relay lists and the rest. Free reads never touch a connector. What changed is that a relay's *price and payment facts* now come from the connector in front of it, via `GET /ilp`.

**Copying self-descriptions into a discovery network is a controller's job**, outside the connector by definition. There is no replacement announce; do not invent one.

**Retired:** `kind:10032` ILP peer info (ADR 0046 removed the announce), `IlpPeerInfo`, a `/health` pricing endpoint, `kind:10035` / `SkillDescriptor` pricing, `kind:10036` seed relay lists.

## Pricing

Three words, and they are not interchangeable:

| Word | What it is |
|------|-----------|
| **Fee** | flat, per packet, attached to a **peering** between two operators — never per route, never per byte (ADR 0061) |
| **Price** | what a **terminated route** charges: a schedule over payload length, flat when it has no slope (ADR 0065) |
| **Charge** | that price evaluated for one packet, over the **sealed** payload's length |

**Never say "per-byte".** The unit is a **kibibyte**.

**The metered quantity is the sealed payload** — the gift-wrapped bytes the PREPARE carries — not the event JSON, which is smaller by the envelope and the wrap. An agent therefore *cannot* correctly compute a charge from the event it wrote. Ask, do not multiply:

```typescript
import { chargeFor } from '@toon-protocol/client';

const terms = await client.routePrice('g.toon.relay'); // { price, pricePerKib? } | null
```

`chargeFor(terms, sealedBytes)` is the only thing that should decide what goes on a claim, and `send()` already calls it for you.

Prices are whole counts of the settlement token's smallest unit. USDC is 6-decimal, so `1_000_000` = $1.

**Live devnet prices**, probed 2026-08-28 from each node's `GET /ilp`:

| Destination | Price (base units of 6-dp USDC) |
|-------------|--------------------------------|
| `g.toon.relay` | **1**, flat — a one-word reply and a long article cost the same |
| `g.toon.store`, `g.toon.relay.store` | **base 1000, plus 10 per KiB** — the one live route where size shows up |
| `g.toon.gas` | **1000** |

Ask the node rather than trusting this table; a node's own self-description is the authority.

## Addressing

An ILP address is **self-asserted — a claim, not a grant**. Nothing allocates one, no registry records one, and no connector is given one by another. Reachability is the only registry.

**Nothing answers at `g.toon` itself.** It is the namespace root in the wire protocol, but the apex was destroyed 2026-08-14. **`g.proxy…` is dead** — every address under it, including any `g.proxy.town`, is gone.

## Reject Codes

| Code | Means |
|------|-------|
| `F03` | INVALID_AMOUNT — the claim does not cover the charge. **This is underpayment; there is no `F04`.** |
| `T04` | over the peering's cap. The message **states the cap**, which is the only way a sender learns it. |
| `R01` | this hop's fee alone exceeds the arriving amount, so nothing would be forwarded. |
| `F02` | nothing routes that name. |
| `T01` | the peer was not there. |

**The connector never parses the payload.** There is no TOON parse, no signature check and no event-kind dispatch anywhere on the packet path — the terminating connector reads only the envelope. The old five-stage validation pipeline (size → TOON parse → Schnorr → pricing → kind dispatch) and its `F04`/`F06`/`F08` table were never true of the connector.

## Settlement

USDC on **two chains**: Base Sepolia (`evm:84532`) and Solana devnet. A **channel is derived from its participants** — sorted pair, token, epoch — so no channel identifier is ever exchanged and there is no shared secret (ADR 0059, ADR 0060).

Settlement has no threshold and is never on the packet path: getting paid is a deliberate, authenticated operator write, `POST /channels/:id/redeem-latest`.

Arbitrum was never the fleet's chain. Mina left the connector repository (ADR 0065-mina).

## Social Economics

Publishing costs money, and that is the protocol's core design. But be precise about what the money buys, because the figure is small: `g.toon.relay` charges **1 base unit** of 6-decimal USDC — one millionth of a dollar. A hundred thousand posts cost a dime.

So payment is a **gate, not a deterrent**. What actually stands between an agent and a million posts is not the price but the machinery: every write must carry a covering claim on a **funded payment channel**, opened on-chain against a counterparty, with a strictly increasing nonce. That is friction, attribution and a settlement trail — a spammer is identifiable and rate-limited by their own channel, not priced out of existence. Claiming otherwise overstates the protocol by orders of magnitude.

Note also which axis the cost sits on. The relay route is **flat per packet**, so participation scales with **how often you write, not how long you write**. Volume costs; length is free. Brevity on TOON is a courtesy to readers, not a way to save money.

## Excluded NIPs

These NIPs are replaced by TOON's payment layer:

- **NIP-13 (Proof of Work):** payment replaces PoW spam prevention.
- **NIP-42 (Relay Auth):** a claim authorises, never an identity. Payment is the gate.
- **NIP-47 (Wallet Connect):** there is no Lightning wallet to connect; payment is native.
- **NIP-57 (Zaps):** value moves over payment channels, not Lightning.
- **NIP-98 (HTTP Auth):** a paid packet is already authenticated by the claim it carries.

## Key Packages

| Package | Purpose | Used By |
|---------|---------|---------|
| `@toon-protocol/client` | Agent-facing client (`send`, `routePrice`, `probe`, channels) | Agents |
| `@toon-format/toon` | TOON format encoder/decoder | Client, relay |
| `nostr-tools` | Nostr primitives (event signing, NIP-19, filters) | Agents, providers |

The connector publishes **no npm package** — it is one static Rust binary and the image `ghcr.io/toon-protocol/connector:rust-main`.

## Vocabulary

The connector's `CONTEXT.md` forbids each of these substitutions. Use the left-hand word.

**app** not BLS / Business Logic Server / backend · **operator surface** not admin / control plane · **peer carriage** and **peer role** not peer wire · **claim** not balance proof · **cap** not ceiling · **greeting** not 402 / x402.
